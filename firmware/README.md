# Прошивка

Здесь две прошивки на одном движке:

- **Плата rev B** (`src/keychain/`, среда `keychain`) — своя плата брелока на nRF52840 ([`hardware/rev-b`](../hardware/rev-b/README.md)): все датчики, голос, встречи по Bluetooth, сон и выключение. Описана [ниже](#плата-rev-b).
- **Стенд** (`src/main.cpp`, среды `esp32*`) — плата ESP32, модуль SSD1306 0.96″ и, по желанию, сенсорная кнопка TTP223 и пассивная пищалка. Цель стенда — увидеть все 139 эмоций на живой панели без своей платы.

Движок тот же, что в симуляторах, без изменений.

# Стенд на ESP32

## Что нужно

- **Плата**, любая из:
  - ESP32-C5-DevKitC-1;
  - DevKit на ESP-WROOM-32;
  - ESP32-C3 SuperMini или DevKitM;
  - ESP32-S3 DevKitC.
- **Модуль экрана:** SSD1306 128×64 по I2C, 4 вывода.
- **Кнопка** (по желанию): сенсорная TTP223.
- **Пищалка** (по желанию): пассивная, без генератора. Подойдёт пьезодиск, пьезопищалка 9–12 мм или модуль KY-006. Активная пищалка с генератором не подойдёт: она пищит одним тоном.
- Провода Dupont и USB-кабель с линиями данных. Кабель «только для зарядки» не подойдёт.

**ESP8266 (Wemos D1 mini) не подходит.** Каталог эмоций занимает около 65 КБ констант. У ESP8266 они по умолчанию лежат в ОЗУ, а свободно там около 45 КБ.

## Подключение

| Модуль экрана | ESP32-C5 | ESP32 DevKit | ESP32-C3 | ESP32-S3 |
|---|---|---|---|---|
| VCC | 3V3 | 3V3 | 3V3 | 3V3 |
| GND | GND | GND | GND | GND |
| SCL | GPIO 1 | GPIO 22 | GPIO 9 | GPIO 9 |
| SDA | GPIO 0 | GPIO 21 | GPIO 8 | GPIO 8 |
| **Кнопка TTP223** | | | | |
| VCC | 3V3 | 3V3 | 3V3 | 3V3 |
| GND | GND | GND | GND | GND |
| I/O | GPIO 6 | GPIO 4 | GPIO 3 | GPIO 4 |
| **Пищалка** | | | | |
| + | GPIO 8 | GPIO 25 | GPIO 4 | GPIO 5 |
| − | GND | GND | GND | GND |

- **Подключайте по надписям на модуле, а не по порядку выводов.** У одних модулей порядок `VCC GND SCL SDA`, у других `GND VCC SCL SDA`. Если перепутать питание, модуль сгорит.
- **Питание 3.3 В.** Модули работают и от 5 В, но тогда подтяжки на модуле тянут SDA и SCL к 5 В, а входы ESP32 на это не рассчитаны.
- **ESP32-C5-DevKitC-1:**
  - 3V3, GND, GPIO 0, 1 и 6 стоят на одной гребёнке (J1);
  - у платы два порта USB-C: сообщения стенда идут через порт **UART**, кабель втыкайте в него;
  - кнопка **BOOT** на самой плате работает как кнопка стенда, провода не нужны.
- **У TTP223 три провода, а не один:** VCC, GND и I/O. Без питания модуль молчит. Каждое касание печатается в Serial: «Кнопка: тап».
- **Адрес** 0x3C или 0x3D (перемычка на обороте модуля). Прошивка находит его сама.
- **Модули 1.3″** обычно на SH1106. Если картинка сдвинута или по краю мусор, введите команду `h`.
- **Пищалку** можно подключить прямо к выводу, лучше через резистор 100–220 Ом. Без пищалки стенд работает так же, только молча.
- **Другие выводы** задаются в `platformio.ini`: `-DPIN_SDA`, `-DPIN_SCL`, `-DPIN_BUTTON`, `-DPIN_BUZZER`.
- **Обычная кнопка** вместо сенсорной ставится между выводом и GND. Тогда добавьте `-DBUTTON_ACTIVE_LOW=1` в `build_flags`.

## Как прошить

### Из браузера, без установки

1. Скачайте готовый файл:
   - GitHub → **Actions** → последний зелёный запуск **CI** → артефакт **stand-firmware**;
   - в архиве `stand-esp32c5.bin`, `stand-esp32dev.bin`, `stand-esp32c3.bin` и `stand-esp32s3.bin`.
2. Откройте в Chrome или Edge прошивальщик [olerast.com/flash](https://olerast.com/flash), подключите плату и выберите её порт.
3. Прошейте файл своей платы с адреса `0x0`.
4. Откройте консоль на 115200: там появятся сообщения и можно вводить команды.

Запасной вариант — прошивальщик Espressif [espressif.github.io/esptool-js](https://espressif.github.io/esptool-js/): **Connect** → файл с адреса `0x0` → **Program** → **Disconnect** → в разделе **Console** скорость 115200 и **Start**.

### VS Code + PlatformIO

1. Поставьте расширение **PlatformIO IDE**.
2. Откройте папку `firmware/`.
3. Выберите среду внизу окна: `esp32c5`, `esp32dev`, `esp32c3` или `esp32s3`.
4. Нажмите **Upload**, затем **Serial Monitor**.

Первая сборка скачивает ядро и компилятор и идёт несколько минут.

### Из терминала

```sh
pip install platformio
cd firmware
pio run -e esp32c5 -t upload      # или -e esp32dev, -e esp32c3, -e esp32s3
pio device monitor                # 115200, выход — Ctrl+C
```

Если порт не появляется, поставьте драйвер USB-моста платы: CH340 или CP210x. Если прошивка не начинается, зажмите **BOOT**, нажмите **RESET** и отпустите **BOOT**.

## Что умеет стенд

| Режим | Что происходит |
|---|---|
| **живой** (при старте) | Работает характер: моргает, оглядывается, скучает, засыпает ночью, реагирует на кнопку |
| **показ** | Все эмоции по кругу, по 3.5 с на каждую. Номер и имя печатаются в Serial |
| **ручной** | Одна эмоция, выбранная командой |

**Кнопка:**

| Действие | Результат |
|---|---|
| Касание | В живом режиме — тап. В показе и ручном режиме — следующая эмоция |
| Два касания подряд | Двойной тап |
| Удержание 1.5 с | Переключение «живой» ↔ «показ» |

**Команды в Serial** (каждая — строкой, затем Enter):

| Команда | Что делает |
|---|---|
| `laugh` или `42` | показать эмоцию по id или по номеру из [каталога](../docs/emotions.md) |
| `n` / `p` | следующая или предыдущая эмоция |
| `s` или `s 1500` | показ всех эмоций, можно задать мс на каждую |
| `a` | живой режим |
| `e tap`, `e shake`, `e music`, `e dark` … | событие для характера, как будто сработал датчик |
| `c blink`, `c sneeze`, `c glitch` … | жест |
| `+` / `-` / `b 200` | яркость: ярче, темнее, точное значение 0–255 |
| `dim` | автояркость вкл/выкл: в живом режиме ночью и во сне экран в 4 раза тусклее, в темноте — в 16 |
| `u` / `r` / `d` | перевернуть экран / ретро-строки / дрейф против выгорания |
| `h` | переключить SSD1306 ↔ SH1106 |
| `t 23:30` | время суток для характера (часов на стенде нет, старт с 12:00) |
| `l` / `i` / `?` | список эмоций, клипов и событий / состояние / помощь |
| `v` | каждые 10 с печатать кадры в секунду, байты и время на кадр |

**Характер, рост и сцены:**

| Команда | Что делает |
|---|---|
| `me` | кто я: позывной, характер, редкость, день, опыт, импланты, открытые эмоции |
| `theme classic` / `cyber` / `retro` | тема оформления, сохраняется во флеше |
| `x hack`, `x new_year`, `x duel` … | сцена: `boot hack data_rain error404 reboot hide upgrade new_year birthday halloween greet duel chat achievement charge shutdown banner bsod visor screensaver` |
| `surprise` | случайный сюрприз прямо сейчас |
| `xp 200` / `day` / `steps 3000` | опыт, новый день, шаги — проверить импланты и сцену апгрейда |
| `meet` / `meet old` | рядом новый или знакомый брелок |
| `meet again` | тот же сосед, что в прошлый раз. Дружба растёт по дням встреч: `day`, `meet again`, `day`, `meet again` — и вы приятели |
| `meet mentor` | старший брелок: дарит эмоцию из следующего импланта |
| `friends` | знакомые брелоки: дни встреч и уровень дружбы, хранятся во флеше |
| `ach` | 24 достижения: что уже есть и за что остальные |
| `knock` | стенд сам выстукивает «Shave and a haircut», брелок отвечает «two bits» |
| `bat 47` | заряд в процентах для сцены зарядки (`e charge_start`) |
| `off` | выключиться: LOW BATTERY → GOODNIGHT, сон до кнопки |
| `duel win` / `duel lose` | дуэль: победа открывает эмоцию досрочно, потом — секретный разговор |
| `date 2026-12-31` | дата для праздников и пасхалок: `2026-03-14` — день π, `2026-04-01` — розыгрыш, `2026-04-12` — POEKHALI!, `2026-02-13` — пятница, 13-е (часов на стенде нет) |
| `t 13:37` | время-пасхалки: 13:37, 11:11, 12:34, 04:04 |
| `bday 05-14` | твой день рождения, сохраняется во флеше |
| `tilt 1 0` / `jerk -1 0` | наклон: зрачки скатываются вбок / резкое движение |
| `serial 75` / `serial` | посмотреть другой брелок (номер 75 — легендарный) / вернуть свой |
| `unlock all` / `reset yes` | открыть все эмоции / начать рост заново |

**Звук** ([голос брелока](../docs/sound.md)):

| Команда | Что делает |
|---|---|
| `snd` | пищалка вкл/выкл, сохраняется во флеше |
| `say laugh` | реплика: `boop happy laugh sad angry surprise scared love sleepy hello goodbye question idea error charge_start charge_full battery_low level_up friend_hi duel win lose boot` |
| `chat` | секретный разговор шифром с выдуманным соседом: слышны обе стороны |
| `x birthday`, `x hack` … | сцены играют свою музыку |

У каждого характера свой голос. Брелок отвечает на касания и события не каждый раз, а по своей разговорчивости. С 23:00 до 6:00 говорит только о важном, и тихо. После `duel win` или `duel lose` сразу идёт секретный разговор. Каждая реплика печатается в Serial: «Звук: laugh».

Персонаж берётся из серийного номера чипа: у каждой платы свой. Рост, тема и день рождения хранятся во флеше и переживают перезагрузку. Запись роста старой версии переносится при первом запуске новой прошивки. При включении играет загрузка OLERAST LINK. В ручном режиме (`laugh`, `42`) можно показать любую эмоцию, даже ещё не открытую.

Команду с неверным числом или форматом (`t 25:99`, `xp -1`, `b 300`) стенд не выполняет, а подсказывает формат. Строку длиннее 63 символов пропускает целиком.

Экран можно отключить и подключить на ходу. Стенд заметит пропажу по ошибкам I2C и будет искать модуль раз в 2 с. Найдя, заново инициализирует его и перерисует весь кадр. Если отправка сорвалась из-за помехи, следом уходит весь кадр целиком.

`millis()` переполняется раз в 49.7 суток. Сроки стенд сравнивает только через `time_reached`, а часы и счёт дней ведёт по 64-битному времени работы.

## Что проверить на живой панели

- [ ] **Весь каталог** (`s`), с 30–50 см и с расстояния брелока на рюкзаке. Запишите номера эмоций, которые не читаются.
- [ ] **Мелкие значки:** Zzz, капля пота, ноты, сердечки, звёзды, вопрос. Проверьте, не сливаются ли они.
- [ ] **Похожие пары:**
  - `scared` и `surprised`;
  - `sad` и `tired`;
  - `angry` и `annoyed`.

  Различаются ли они без подписи?
- [ ] **Плавность.** Нет ли рывков в переходах и жестах. Команда `v` показывает время шины на кадр.
- [ ] **Яркость** `b 30`, `b 127` и `b 255`: при какой лицо читается в комнате и на улице.
- [ ] **Ретро-режим** (`r`): как он выглядит и не теряется ли читаемость.
- [ ] **Автояркость:** `t 23:30` и `e dark` — экран тускнеет, `e light` и `t 12:00` — возвращается. Достаточно ли видно лицо на минимуме.
- [ ] **Голос:** `say laugh`, `x birthday`, `duel win`. Различимы ли ноты, не режет ли уши, слышно ли в шумной комнате. Ночью (`t 23:30`) реплики тише.
- [ ] **Ретро-тема** (`theme retro`): читаются ли эмоции крупными пикселями.
- [ ] **Новые сцены:** `x achievement`, `x charge`, `x bsod`, `x visor`, `x screensaver` (ждать 10 с до угла), `x banner`. Читается ли мелкий текст.

Эмоции, которые не читаются, удобно заводить [задачей по шаблону](https://github.com/olerast67/emotion-keychain/issues/new/choose).

## Как устроено

| Файл | Что внутри |
|---|---|
| `src/main.cpp` | режимы, кнопка, команды Serial, статистика |
| `src/ssd1306.*` | драйвер SSD1306/SH1106. Шлёт только изменённые окна командами `0x21`/`0x22` порциями по 64 байта; у SH1106 — постранично, со смещением на 2 столбца |
| `platformio.ini` | среды `esp32c5`, `esp32dev`, `esp32c3` и `esp32s3` с выводами под каждую |
| `host/` | проверка прошивки на ПК: заглушки Arduino и эмулятор памяти контроллера |

Сборка идёт на ядре Arduino-ESP32 3.3 через платформу [pioarduino](https://github.com/pioarduino/platform-espressif32). Официальная платформа PlatformIO осталась на ядре 2.0, а в нём нет ESP32-C5. Кроме обычной прошивки, сборка кладёт склеенный файл `.pio/build/<среда>/firmware.factory.bin` — его и прошивают из браузера с адреса `0x0`.

Проверку на ПК запускает `ctest` из корня репозитория, вместе с тестами движка. Тест прогоняет настоящий `main.cpp` на виртуальном времени. Проверяется:
- кнопка, все команды и неверный ввод;
- показ всего каталога;
- SH1106 и адрес 0x3D;
- автояркость;
- помеха на шине и переподключение экрана;
- перенос старой записи роста;
- переполнение `millis()` в ручном режиме, на зарядке и во сне;
- пищалка: мелодия при старте, реплики, выключатель, тихие часы, разговор после дуэли;
- темы, зарядка с процентом, секретный стук, достижения, дружба по дням, выключение, пасхалка 13:37.

После каждого прохода цикла память «экрана» должна совпадать с кадром движка.

# Плата rev B

Прошивка своей платы: модуль Raytac MDBT50Q (nRF52840) с SoftDevice S140, ядро Arduino от Adafruit. Описание платы для сборки — [`boards/keychain_revb.json`](boards/keychain_revb.json) и [`variants/keychain_revb`](variants/keychain_revb).

## Что умеет

| Что | Как |
|---|---|
| **Лицо** | весь движок: 139 эмоций, характер по серийному номеру чипа, рост, достижения, темы, пасхалки |
| **Касания** | аппаратный детектор LIS3DH: тап и двойной тап по корпусу |
| **Движение** | тряска, сильная тряска, падение и удар, «взяли в руки», покой, вверх ногами, ходьба и бег, шаги в опыт; зрачки скатываются за наклоном и отстают при рывке |
| **Звук** | микрофон PDM: хлопок, речь, музыка, тишина. Слушает, только пока брелок бодрствует. Свою пищалку и свой мотор микрофон не слышит: пока они работают и 150 мс после, звук не считается. Толчки своего мотора — не касания: пока он работает и 150 мс после, тряска, удар, падение и касания не считаются |
| **Свет** | LTR-303ALS: темно, светло, солнце; яркость экрана по суткам и свету |
| **Температура** | датчик чипа: холодно, жарко; от неё же зависит, можно ли заряжать |
| **Голос** | пищалка в противофазе на двух выводах: реплики, музыка сцен, разговор шифром |
| **Вибро** | короткие узоры на встречи и дуэли |
| **Встречи** | реклама и прослушивание BLE без соединения: приветствие, дружба по дням, подарок старшего, дуэль и разговор шифром одновременно на двух брелоках ([встречи](../docs/encounters.md)) |
| **Батарея** | заряд в процентах, сцена зарядки, экорежим при малом заряде, выключение на пустой ячейке. Заряд — только при 10–42 °C по кристаллу nRF ([зарядка](#зарядка)) |
| **Сон** | процессор спит между кадрами; экран гаснет в кармане через минуту; полное выключение кнопкой |
| **Память** | рост, знакомые и настройки — одной записью в журнале из трёх своих страниц флеша (0xEA000–0xECFFF, их резервирует загрузчик). Запись дописывается без стирания, запись — 320 байт, страница стирается раз в 12 записей; обрыв питания посреди записи оставляет прошлую целой (тест `storage_tests`: 3000 обрывов). У записи есть заголовок с длинами частей: прошивка, у которой они выросли, прочтёт старую запись. Обычная запись — раз в 10 минут, новые эмоции — сразу, настройки с консоли — через 3 с после последнего изменения и не чаще раза в 10 с. Пока звучит пищалка или работает мотор, обычная запись ждёт: стирание страницы останавливает цикл на доли секунды |
| **Надёжность** | сторожевой таймер 8 с с первых строк `setup`. Ведомого, зажавшего SDA, отпускают такты SCL, а шину, зажатую намертво, прошивка не трогает — и шину датчиков, и шину экрана: обмен по ней висел бы до сброса, и брелок перезагружался бы по кругу без лица, консоли, зарядки и выключения кнопкой. Перед запуском шины линии проверяются и на замыкание между собой (перемычка SCL–SDA на соседних выводах J2 в покое не видна, а обмен с ней виснет). Экран с зажатой шиной обесточен, повтор — всё реже, до раза в минуту; SDA, которую контроллер экрана зажал посреди работы, прошивка видит между обменами и перезапускает его питание. Датчики, которые перестали отвечать или потеряли настройки, перезапускаются: проверка раз в 10 с, неудачный перезапуск — всё реже, до раза в 5 минут. Экран, который не отвечает, обесточивается на секунду с SDA и SCL в нуле — так его питание спадает ниже 1 В и зависший контроллер сбрасывается. Время без скачка через 48.5 суток, консоль не блокирует цикл |

## Кнопка

| Нажатие | Что делает |
|---|---|
| Короткое | «кнопка» для характера; будит погасший экран |
| Двойное | дуэли вкл/выкл (баннер DUELS ON / DUELS OFF) |
| Удержание 3 с | «спокойной ночи» и полное выключение; проснётся от кнопки или от USB. На зарядке — экран, датчики и эфир гаснут, зарядка и часы идут; кнопка включает обратно (полный сон на USB нельзя: кнопка при USB включает загрузчик) |
| Держать и подключить USB | загрузчик: появляется диск KEYCHAIN ([все способы](#загрузчик-и-обновление-по-usb)) |

Кнопку, которой будят, часто держат, «пока не включится». Такое нажатие не считается ни коротким, ни удержанием для выключения.

## Первая прошивка: загрузчик по SWD

Новый модуль пустой, поэтому один раз нужен программатор. Он записывает загрузчик Adafruit вместе с SoftDevice S140 — готовый файл [`bootloader/emotion_keychain_revb_bootloader-0.11.0-keychain_s140_6.1.1.hex`](bootloader) — или сразу всё вместе с прошивкой (`firmware-factory.hex`, ниже). Дальше всё обновляется по USB.

**Питание и уровни — прочитать до подключения.**
- **Плату питают от USB-C**, и на заводе тоже. Ячейки на этом шаге может не быть.
- **На чистом чипе выводы работают при 1.8 В.** REG0 модуля по умолчанию даёт 1.8 В, а 3.3 В включаются только после сброса, когда в UICR уже записано значение. Весь сеанс программатора на новой плате идёт при VDD = 1.8 В.
- **J3, площадка 1 — VTref.** По ней программатор только *меряет* напряжение платы и подстраивает под него свои уровни. Питание на неё не подавать и с выходом 3.3 В программатора не соединять: это выход регулятора модуля.
- **Программатор — с уровнями по VTref:** J-Link EDU Mini V2, J-Link BASE или PLUS. J-Link EDU Mini V1 работает только с 3.3 В. Raspberry Pi Pico с прошивкой [debugprobe](https://github.com/raspberrypi/debugprobe) всегда выдаёт 3.3 В: с ним — только через преобразователь уровней, сторона платы которого питается от VTref, или для платы, которая уже работает при 3.3 В (загрузчик или заводской файл записан и был сброс).
- Резисторов в SWDIO и SWDCLK на плате нет: рядом с модулем для них не осталось места под дорожки. Если подключить программатор с 3.3 В к чистой плате (1.8 В) напрямую, ток пойдёт через защитные диоды выводов модуля. Так не делать: только программатор, который следует VTref, или преобразователь уровней.

**Подключение** к J3 на обороте платы (Tag-Connect TC2030):
- кабель **TC2030-CTX-NL** — вилка 10 контактов 1.27 мм, втыкается прямо в J-Link EDU Mini;
- или тонкие провода, припаянные к площадкам: 1 — VTref, 2 — SWDIO, 4 — SWDCLK, 5 — GND. Площадки 3 и 6 не подключены.

**Команды** (одна из):

```sh
# J-Link: nrfjprog из nRF Command Line Tools
nrfjprog -f nrf52 --recover
nrfjprog -f nrf52 --program firmware-factory.hex --verify --reset

# CMSIS-DAP (Pico debugprobe через преобразователь уровней): pyOCD
pip install pyocd
pyocd erase -t nrf52840 --chip
pyocd flash -t nrf52840 firmware-factory.hex
```

`--recover` и стирание всей памяти снимают защиту отладки: на новых ревизиях nRF52840 она включена с завода. Они же стирают UICR, поэтому заводской файл записывается целиком.

**`firmware-factory.hex`** сборка кладёт рядом с `firmware.uf2` (в CI — `keychain-revb-factory.hex`). В нём:
- загрузчик и SoftDevice;
- приложение;
- отметка загрузчику «приложение рабочее» (0xFF000 = 1, как `flash-skip-crc` в его Makefile);
- **UICR.REGOUT0 = 0xFFFFFFFD (3.3 В).** Значение действует со сброса, которым кончается прошивка: загрузчик и прошивка с первого запуска работают при 3.3 В, лишней перезагрузки на запись UICR нет.

Брелок после программатора сразу показывает лицо. Этот же файл отдают на завод, если сборщик прошивает платы сам (PCBWay — «Firmware loading»): тогда J3 вам не нужен вовсе. Только загрузчик, без прошивки, записывают так же, с файлом из `bootloader/`; 3.3 В на REG0 он ставит сам при первом запуске и перезагружается.

После этого брелок, подключённый по USB, показывается диском **KEYCHAIN** (если записан только загрузчик) или сразу показывает лицо.

## Загрузчик и обновление по USB

**Перетащить файл.** Скопируйте `firmware.uf2` на диск KEYCHAIN. Брелок перезагрузится с новой прошивкой.

**Как попасть в загрузчик.** Загрузчик смотрит на кнопку только в момент сброса, поэтому на работающем брелоке жесты ловит сама прошивка.

| Как | Когда срабатывает |
|---|---|
| Зажать кнопку и, не отпуская, подключить USB | брелок работает или его только что разбудили этой же кнопкой. Кнопку зажали не раньше чем за 10 с до USB — в том числе если удержание уже выключает брелок: сцена прощания прошла, экран погас, а кнопку всё держат |
| Команда `dfu` в консоли | прошивка работает, консоль открыта |
| На брелоке, выключенном на зарядке, держать кнопку дольше 10 с | через 10 с прошивка перезагружается с зажатой кнопкой, и загрузчик её видит |
| Прошивка зависла: держать кнопку при подключённом USB | сторожевой таймер сбросит плату за 8 с, загрузчик увидит кнопку и USB |
| Ничего не делать | прошивки нет или она испорчена |

- **Выключенный брелок на батарее** нажатие кнопки сначала будит: без USB загрузчик кнопку не замечает. Держите её и подключите USB — сработает первая строка.
- **Кнопку держат дольше 10 с** (залипла или ею будили и не отпускают) — подключение USB загрузчик не включает: иначе брелок с залипшей кнопкой не заряжался бы. Если диск KEYCHAIN появляется при каждом подключении к выключенному брелоку, кнопка залипла.
- **Сколько загрузчик ждёт.** Компьютер нашёл диск — пока USB не отключат. Зарядка от розетки — 3 с после `dfu` или жеста, 10 с после сброса с зажатой кнопкой. Потом запускается прошивка.
- **Часы** после жеста и `dfu` продолжаются: перед загрузчиком прошивка записывает их с точностью до минуты, а уходит в него программным сбросом. Время, проведённое в загрузчике, не считается.
- **В загрузчике ячейка не заряжается** ([зарядка](#зарядка)).

**PlatformIO:**

```sh
cd firmware
pio run -e keychain -t upload && pio device monitor
```

Перед сборкой `tools/version.py` берёт версию из `git describe` (метка или короткий хэш коммита, `-dirty` — с незакоммиченными правками; без git — `unknown`). Её печатают приветствие консоли и команда `ver`: так видно, какая сборка залита в брелок. Сборка кладёт в `.pio/build/keychain/` файлы `firmware.hex`, `firmware.zip` (DFU по USB), `firmware.uf2` и `firmware-factory.hex` (всё для программатора). После сборки `tools/uf2.py` проверяет, что прошивка кончается раньше журнала (0xEA000); предел размера в описании платы — те же 802 816 байт с 0x26000. CI собирает файлы на каждый push — архив `keychain-firmware` в разделе Actions, вместе с загрузчиком.

**USB VID/PID — чужие, только для прототипа.** Прошивка показывается как 239A:810B, загрузчик — 239A:010B: это номера Adafruit для платы Raytac MDBT50Q-RX. Перед продажей нужны свои VID/PID (USB-IF); их меняют в `boards/keychain_revb.json` (`hwids`, первая пара — у прошивки) и в `bootloader/emotion_keychain_revb/board.h`.

## Зарядка

- **Зарядник включает прошивка.** Нижний конец R3 (PROG микросхемы MCP73832) — на ножке P0.24 (CHG_EN). Ноль — заряд током 100 мА; ножка отпущена — зарядник выключен, а брелок питается от USB через диод.
- **Заряд — при температуре кристалла nRF от 10 до 42 °C.** Если во время заряда стало холоднее 7 °C или жарче 45 °C, заряд останавливается. Проверка — сразу при подключении USB и дальше раз в 30 с. На морозе литиевую ячейку заряжать нельзя: литий оседает на аноде, и ячейка портится. У MCP73832 нет входа для термистора, поэтому температуру смотрит прошивка.
- **Консоль** пишет «Заряд не идёт: 5 °C, заряжается от 10 до 42 °C», «Заряд остановлен: …» и «Заряд снова разрешён (24 °C)». Пока заряд запрещён, процент заряда неизвестен, и сцена зарядки при подключении не начинается.
- **Это температура кристалла, а не ячейки.** Датчик nRF52840 по документации ошибается до ±5 °C (точность — при кварце 64 МГц; на USB прошивка держит его включённым), а на USB процессор ещё и на несколько градусов теплее воздуха вокруг и ячейки. Поэтому у холода запас большой: заряд с 10 °C по кристаллу. Гарантировать, что ячейку около 0 °C не зарядит, эта проверка не может — это даст только термистор у ячейки (rev C). Брелок с мороза сначала согреть. У жары кристалл ошибается в безопасную сторону.
- **Без прошивки брелок не заряжается:** на чистой плате, в загрузчике и пока прошивка не запустилась, CHG_EN отпущен, и красный светодиод заряда не горит. Новую плату заряжают уже после прошивки.
- **После «Ячейка почти пуста — выключаюсь»** до отсечки платы защиты в ячейке остаётся около 3.6 мА·ч. Выключенный брелок берёт 6–17 мкА — это 9–25 дней. Зарядите его в течение недели, а на долгое хранение оставляйте заряженным примерно наполовину. Нажатие кнопки на пустой ячейке показывает пустую батарею на 1.5 с и снова выключает брелок, не загружая его целиком. После подключения USB это правило снимается.

## Консоль

USB, 115200. Команда `?` выводит список.

| Команда | Что делает |
|---|---|
| `me` | кто я: характер, рост, шаги, дуэли |
| `sensors` | ускорение по осям, свет, звук, температура, питание и заряд, стирания флеша |
| `v`, `v on`, `v off` | печатать события датчиков: tap, shake, music, dark… (`v` — переключить) |
| `t` | показать время или «Время не задано» |
| `t 23:30`, `date 2026-12-31`, `bday 05-14` | время, дата и день рождения — для суточного ритма и праздников |
| `theme cyber` | тема: classic, cyber или retro |
| `snd`, `say laugh` | звук вкл/выкл, реплика |
| `duel`, `ghost` | дуэли вкл/выкл; невидимка — только слушать эфир |
| `ach`, `friends` | достижения, знакомые брелоки |
| `e music`, `x hack` | событие или сцена вручную |
| `b 0…255` | яркость |
| `off`, `dfu` | выключиться; загрузчик для новой прошивки |
| `ver` | версия прошивки (её же печатает приветствие при включении) |

Сообщения без команды: «Заряд не идёт / остановлен / снова разрешён», «Ячейка почти пуста — выключаюсь», «Акселерометр перезапущен», «Датчик света перезапущен», «Шина датчиков зажата: SDA или SCL в нуле», «Шина экрана зажата: SDA или SCL в нуле или замкнуты между собой», «Шина экрана зажата посреди работы: экран перезапускается».

**Часы.** Часов реального времени на плате нет.
- После перезагрузки (сторожевой таймер, `dfu`, загрузчик, новая прошивка) время и дата продолжаются с сохранённых. Перед `dfu`, жестом загрузчика и включением из выключения на USB они записываются с точностью до минуты; после сброса сторожевым таймером время может отстать на 10–20 минут: само по себе оно сохраняется раз в 10 минут.
- После выключения кнопкой, пустой ячейки или первой подачи питания время и дата сбрасываются: сколько брелок спал, неизвестно. Консоль напоминает задать их снова командами `t` и `date`.
- **Без заданных часов нет ночи по часам.** Приглушённый экран, редкий эфир (встречи не слушаются), тихий голос, сон без дела, недосып, пасхалки по времени и достижения за 3 и 5 утра — только по времени, заданному командой `t`. Без него брелок гаснет и засыпает только в темноте, по датчику света.
- **Без часов сутки — это 24 часа работы, и счёт переживает выключение.** Брелок, который выключают на ночь, всё равно доживает до новых суток, и дневные лимиты опыта сбрасываются: три включения по 8–9 часов дают новые сутки. Время, пока брелок выключен, не считается.

## Симуляция платы целиком

До заказа плат прошивку можно прогнать на ПК так, как она будет работать на плате. Код из `src/keychain` собирается без изменений, вместо ядра Adafruit подставлены модели (`host/keychain`):

- **Датчики:** LIS3DH с FIFO на 32 выборки (пакетное чтение только с битом автоприращения, шкала и разрядность — по CTRL1 и CTRL4, переполнение), флагом касания на INT1 (само касание задаёт сценарий: сначала одиночное, у двойного — второе через заданное время) и регистрами, которые сбрасываются при провале питания; LTR-303 с разовыми замерами (пробуждение и 100 мс накопления); микрофон PDM блоками по 32 мс: после включения — нули библиотеки и бросок при выходе на режим, через раз в другом порядке (ноль, бросок, ноль: библиотека отдаёт буфер на блок позже, и какой буфер первый, зависит от прошлого включения).
- **Шины I2C:** микросхема может перестать отвечать и вернуться, ведомый — зажать SDA (отпускает после тактов SCL, пока TWIM выключен — как на плате, где включённый TWIM сам ведёт ножки), SCL — застрять в нуле (обмен висит, как в ядре, до сторожевого таймера). Шина экрана: SCL в нуле или замкнута с SDA (обмен тоже висит), контроллер, зажавший SDA (обмен «проходит», а до экрана не доходит). Буфер Wire — 63 байта, как в ядре; лишний байт — ошибка.
- **Экран:** SSD1306 за ключом питания. После подачи питания в памяти мусор, без инициализации он не включается. Питание модуля после выключения спадает медленно (около 1 В через секунду, а с SDA и SCL в нуле — за десятки миллисекунд), подтяжки на линиях его подпитывают; контроллер сбрасывается, только если питание опустилось ниже 1 В. Контроллер может «зависнуть» и молчать или держать SDA в нуле, пока его так не обесточат.
- **Питание и флеш:** флеш SoftDevice асинхронный (запись по слову, обрыв посреди неё оставляет недописанную запись; стирание 85 мс; «занят»; сбои во время прослушивания эфира); сторожевой таймер, UICR, причина сброса, время ядра с переполнением тиков; USB с провалом питания через диод после отключения, зарядник с ножкой CHG_EN, кнопка, батарея с разрядом по реальному току, в том числе выключенного брелока: ~12 мкА плюс то, что прошивка оставила включённым перед System OFF.
- **Загрузчик:** кнопка при USB в момент сброса и `dfu` — ждёт; компьютер нашёл диск — до отключения USB, иначе 3 или 10 с; потом прошивка с той же причиной сброса. В загрузчике нет заряда.
- **Эфир между платами:** реклама доходит с уровнем сигнала по расстоянию; часть пакетов можно терять.

Каждая плата — свой процесс. Перезагрузка — новый процесс, а флеш журнала — файл на том же адресе 0xEA000, поэтому он переживает перезагрузки и даже обрыв питания посреди записи. Свет, звук, температура и неисправности, заданные сценарием, новый процесс получает заново. После каждого прохода цикла память эмулированного экрана сверяется с кадром движка. Ток считается по состоянию микросхем.

```sh
cmake -B build && cmake --build build -j
./build/keychain_sim ./build/keychain_board build/sim             # все сценарии (~10 мин)
./build/keychain_sim ./build/keychain_board build/sim meeting pocket   # выборочно
```

Любой сценарий можно запустить и отдельно: перед ним всегда идёт `boot`.

| Сценарий | Что проверяет |
|---|---|
| `boot` | первое включение: запись 3.3 В в UICR и перезагрузка, экран и датчики отвечают |
| `sensors`, `sound` | касание и двойное, тряска, 60 шагов, переворот, падение и удар, мороз; хлопок, музыка, тишина, речь |
| `pocket` | темнота, экран гаснет через минуту, ток в кармане, касание и свет возвращают лицо; микрофон после кармана без ложных событий |
| `charge` | начало, конец и отключение зарядки; после отключения от полной — не «мало заряда», заряд ≥ 90 %; на USB кварц 64 МГц запрошен и после перезапуска микрофона; кабель на 1.9–2 с — процент не падает |
| `chargetemp` | мороз −5 °C — зарядник выключен и консоль объясняет; 24 °C — заряд включился; 50 °C — остановлен; пороги 10/7 и 42/45 °C по кристаллу с обеих сторон запаса от дребезга; без ложного «зарядилась»; оценка заряда на USB стоит, пока заряд запрещён |
| `meeting` | два брелока в метре: дуэль у обоих одновременно, один победитель, вибро — около 3 В на моторе, перерыв 10 минут |
| `lossy` | встреча, когда теряется 40 % пакетов: одна и та же сцена у обоих, одновременно |
| `attack` | 4000 испорченных пакетов, поддельные объявления и поток выдуманных брелоков |
| `i2c` | акселерометр и датчик света пропадают и возвращаются, сброс настроек LIS3DH, зажатая SDA, застрявшая SCL (сброс сторожевым таймером, потом лицо без перезагрузок по кругу), датчиков нет при включении |
| `oled` | зависший контроллер экрана сбрасывается обесточиванием (питание ниже 1 В); экрана нет 2 минуты — брелок работает, экран вернулся — лицо; контроллер зажал SDA при включении и посреди работы — экран перезапускается |
| `dbus` | шина экрана: SCL в нуле, SCL замкнута с SDA — не больше одного сброса сторожевым таймером, консоль, зарядка и выключение кнопкой работают; шину отпустили — лицо |
| `clock` | часы потеряны после выключения в 23:30 — днём обычная яркость, эфир слушается; новая плата 11.5 ч без часов — не ночь |
| `off`, `offusb` | выключение кнопкой на батарее и на зарядке, включение, сохранность роста и часов; удержание, которым разбудили, не выключает; кнопка + USB — загрузчик, в том числе через 8 с от нажатия, когда экран уже погас; USB позже 10 с от нажатия — выключение на USB; ток выключенного |
| `dfu` | когда загрузчик включается (жест, `dfu`, 10 с кнопки на зарядке) и когда нет (USB без кнопки, загрузка уже на USB, кнопка зажата дольше 10 с); часы после него на месте. Правила самого загрузчика (кнопка нужна вместе с USB, 3 и 10 с ожидания, нет заряда) — модель, их проверяет только первая плата |
| `stuck` | кнопка залипла при выключении на зарядке: USB отключили — сон без кнопки, будит только USB |
| `watchdog`, `console` | зависание цикла и сброс сторожевым таймером; консоль, которую не читают |
| `cuts` | 30 обрывов питания, 10 из них — посреди записи или стирания флеша |
| `empty` | ячейка разряжается — брелок выключается сам, до отсечки защиты; кнопка на пустой ячейке не загружает его целиком; после зарядки — снова как обычно |
| `wrap` | 48.5 суток работы: переполнение тиков ядра |
| `days` | без часов: 25 ч работы с двумя выключениями — новые сутки ровно через 24 ч работы |
| `day` | расход за день по режимам |

Результаты — в указанной папке: `report.txt`, консоль каждой платы с временем (`console-A.txt`…) и GIF того, что показывали панели (`meeting.gif`, `sensors.gif`, `pocket.gif`). В CI прогон идёт как тест `keychain_sim`, под AddressSanitizer и UBSan.

Чего симуляция не заменяет: аналоговую часть (её проверяли в SPICE, см. [`hardware/rev-b`](../hardware/rev-b/README.md)), настоящие тайминги радио, поведение конкретного модуля экрана, ток утечек, порог касаний (касание в сценарии — готовый флаг CLICK_SRC, а не выборки) и толчки своего мотора по акселерометру, ориентацию осей акселерометра на плате, уровень на CHG_IO при низком VBUS (статус зарядника в модели — чистая логика) и внешние микросхемы при сбросе nRF: в модели каждый сброс начинает LIS3DH, экран и ведомого на шине заново, а на плате они сохраняют состояние (у LIS3DH — настройки, FIFO и флаг касания). Поэтому первую плату всё равно проходят по списку ниже.

## Что проверить на первой плате

- [ ] **Питание.** На контрольной точке 3V3 около 1.8 В, пока плата не прошита, и около 3.3 В после прошивки и сброса. SYS — напряжение ячейки, а от USB — VBUS минус 0.15–0.4 В на диоде, до ~5.4 В.
- [ ] **Загрузчик и прошивка.** После программатора по USB виден диск KEYCHAIN или сразу лицо. Прошивка ставится с диска и через `pio run -t upload`. Жест «зажать кнопку и подключить USB» и команда `dfu` открывают диск; отключили USB — снова лицо.
- [ ] **Экран.** Загрузка, потом лицо. `b 255` и `b 10` — яркость меняется.
- [ ] **Оси акселерометра** (`sensors`). Висит ровно — `y` около +1; правый край вниз — `x` около −1; лежит лицом вверх — `z` около +1. Если знак или ось не те — поправить `kAccMap` в [`board.h`](src/keychain/board.h).
- [ ] **Касания.** Тап и двойной тап по корпусу: `v` печатает `tap` и `double_tap`. Порог — `CLICK_THS` в [`sensors.cpp`](src/keychain/sensors.cpp).
- [ ] **Движение.** Тряска, ходьба 10 шагов (`me` — шаги растут), перевернуть вверх ногами. FIFO читается пачками по 10 выборок (адрес возвращается на OUT_X_L, AN3308). Если наклон взгляда скачет или `sensors` печатает мусор, поставить `kBurst = 1` в [`sensors.cpp`](src/keychain/sensors.cpp).
- [ ] **Свет.** Накрыть датчик ладонью на 5–8 с — `dark`, фонарик — `bright`. Датчик меряет разово, раз в 2 с; из темноты на свет — за 1 с, и сразу, если брелок взяли в руки.
- [ ] **Звук.** Хлопок — `loud`, музыка рядом 5–10 с — `music`, речь — `speech`. `v on` и `say laugh`: своя пищалка событий не даёт. Достать брелок из кармана в тихой комнате — ни `loud`, ни `music`.
- [ ] **Пищалка и вибро.** `say laugh`; встреча двух брелоков — вибро, и толчки мотора не становятся `tap`.
- [ ] **Зарядка.** Подключить USB — консоль молчит или пишет о температуре, горит красный светодиод, `sensors` — «заряжается да». Отключить — сцена гаснет, процент не проваливается.
- [ ] **Заряд в холоде и жаре.** Охладить брелок до 0 °C (в пакете от конденсата, в морозилке) и подключить USB: «Заряд не идёт», светодиод не горит. Согреть — «Заряд снова разрешён». Феном издалека до ~50 °C на корпусе, не выше: «Заряд остановлен». Брелок в загрузчике (диск KEYCHAIN) не заряжается — светодиод не горит.
- [ ] **Встреча.** Два брелока рядом: через 2–30 с приветствие на обоих одновременно. С дуэлями на обоих — дуэль и разговор шифром.
- [ ] **Выключение.** Удержание 3 с — GOODNIGHT и сон; нажатие — снова загрузка. Будить, держа кнопку 5 с, — брелок не выключается снова.
- [ ] **Ток.** Средний ток с лицом и во сне (оценки — в [энергобюджете](../docs/power.md)). В кармане с выключенным экраном — около 0.15 мА. Если заметно больше 0.3 мА, первым проверить, отпускается ли кварц 64 МГц после старта микрофона (`mic_begin` в [`hal.cpp`](src/keychain/hal.cpp)).
- [ ] **Ток выключенного брелока** — меньше 25 мкА. Мерить PPK2 или µCurrent вместо ячейки, брелок выключен удержанием кнопки, USB отключён. Больше — искать утечку: подтяжку SA0 акселерометра (SA0 на VDD, прошивка пишет CTRL_REG0 = 0x90), D1 и R6 у VBUS, выводы экрана при выключенном ключе.

## Как устроено

| Файл | Что внутри |
|---|---|
| `src/keychain/main.cpp` | цикл: датчики → характер → экран и голос; кнопка, встречи, заряд, сон, консоль |
| `src/keychain/sensors.*` | LIS3DH (FIFO, касания, проверка настроек) и LTR-303ALS |
| `src/keychain/hal.*` | питание и REG0, заряд и CHG_EN, температура, пищалка на PWM3, вибро, микрофон PDM, сторожевой таймер, освобождение шины I2C, выключение |
| `src/keychain/radio.*` | реклама и прослушивание BLE по расписанию |
| `src/keychain/storage.*` | журнал во флеше; проверка на ПК — `host/storage_test.cpp` |
| `src/keychain/board.h` | выводы платы и оси акселерометра |
| `tools/uf2.py` | после сборки: проверка конца прошивки, `firmware.uf2` и `firmware-factory.hex` с REGOUT0 |
| `host/keychain/` | симуляция платы: модели микросхем (`models.cpp`), плата-процесс (`board.cpp`), координатор и сценарии (`keychain_sim.cpp`) |
| `bootloader/` | вариант загрузчика Adafruit для платы и готовый `.hex` ([как пересобрать](bootloader/README.md)) |

Обработка датчиков (`face/sensing.h`) и встреч (`face/encounter.h`) лежит в движке и проверяется тестами на ПК. Прошивка только читает железо и передаёт числа.
