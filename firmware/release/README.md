# Готовые файлы прошивки

> **Эти файлы — для прототипов:** в них USB-номера Adafruit (239A:810B у прошивки, 239A:010B у загрузчика) — раздел `[sale]` в `firmware/platformio.ini` как в репозитории. Брелоки на продажу прошивают своей сборкой со своими номерами в `[sale]` — и при сборке, и при обновлениях проданных брелоков (свой `firmware.uf2`, не `keychain-revb.uf2`).

Здесь лежат готовые файлы прошивки брелока (плата rev B) и стенда на ESP32. Все собраны из одного коммита, собирать ничего не нужно. Откуда ещё можно взять прошивку, написано в [README прошивки](../README.md#где-взять-файлы).

## Файлы

| Файл | Что внутри | Куда и как |
|---|---|---|
| `keychain-revb-factory.hex` | Всё сразу: загрузчик Adafruit с SoftDevice S140, прошивка брелока, отметка загрузчику «прошивка рабочая» и UICR.REGOUT0 = 3.3 В | Программатором по SWD на новую плату ([первая прошивка](../README.md#первая-прошивка-загрузчик-по-swd)) или заводу для «Firmware loading». Только для прототипов: на брелоки для продажи — `firmware-factory.hex` своей сборки. После записи брелок сразу запускает прошивку: лицо — если экран уже стоит; без экрана проверка — `ver` и `sensors` в консоли |
| `keychain-revb.uf2` | Только прошивка брелока | Перетащить на диск KEYCHAIN ([обновление по USB](../README.md#загрузчик-и-обновление-по-usb)). Загрузчик на плате уже должен быть. Проданным брелокам — не этот файл, а `firmware.uf2` своей сборки для продажи |
| `keychain-revb-dfu.zip` | Только прошивка брелока, пакет DFU | Через `adafruit-nrfutil` по USB, когда брелок в загрузчике. Нужен, только если диск не годится, например для своего скрипта |
| `stand-esp32c5.bin` | Стенд для ESP32-C5-DevKitC-1 | Прошивальщик в браузере, с адреса `0x0` ([стенд](../README.md#из-браузера-без-установки)) |
| `stand-esp32dev.bin` | Стенд для DevKit на ESP-WROOM-32 | так же |
| `stand-esp32c3.bin` | Стенд для ESP32-C3 SuperMini или DevKitM | так же |
| `stand-esp32s3.bin` | Стенд для ESP32-S3 DevKitC | так же |
| `SHA256SUMS` | Контрольные суммы файлов: сумма SHA-256 и имя файла, по строке на файл | [Проверка](#проверка-файлов) |
| `README.md` | Этот файл | |

Загрузчик без прошивки лежит отдельно, в [`../bootloader/`](../bootloader/README.md). Обычно он не нужен: он уже есть внутри `keychain-revb-factory.hex`.

Брелок rev B прошивают только файлами `keychain-revb-*`. Файлы стенда для брелока не годятся, и наоборот. Стенд свою версию не печатает: она та же, что вверху этого файла.

Пакет DFU, если он нужен: брелок переводят в загрузчик (кнопка + USB или команда `dfu`), затем

```sh
pip install adafruit-nrfutil
adafruit-nrfutil --verbose dfu serial --package keychain-revb-dfu.zip -p <порт загрузчика> -b 115200 --singlebank
```

Порт загрузчика — `/dev/ttyACM0` в Linux, `/dev/cu.usbmodem…` в macOS, `COM…` в Windows; в загрузчике его номер может быть другим, чем у работающего брелока.

## Проверка файлов

Сверьте суммы до прошивки, особенно если файлы скачаны по одному через браузер. Не сошлось — файл повреждён или это не тот файл: скачайте заново.

В Linux:

```sh
cd firmware/release
sha256sum -c SHA256SUMS
```

В macOS:

```sh
cd firmware/release
shasum -a 256 -c SHA256SUMS
```

У каждого файла должно быть `OK`. Если команда пишет, что файла нет, а вы его не скачивали, это не ошибка.

В Windows (PowerShell, в папке с файлами):

```powershell
Get-FileHash keychain-revb-factory.hex -Algorithm SHA256
```

Сравните 64 знака с первой колонкой строки этого файла в `SHA256SUMS`. Регистр букв не важен.

Файлы этой папки git отдаёт байт в байт, не меняя концы строк, даже в Windows с `core.autocrlf` (так задано в `.gitattributes`). Поэтому у файла из клона сумма тоже должна сойтись. Не сошлась — файл повреждён или не той версии: скачайте его заново (на GitHub — кнопка «Download raw file») и сверьте ещё раз. Не сходится снова — не прошивайте.

## Какая прошивка в брелоке

Консоль брелока — USB, 115200 бод. Подключите брелок кабелем с линиями данных (кабель «только для зарядки» порта не даст) и откройте порт любым терминалом на 115200:

- **Arduino IDE:** Tools → Port — порт брелока, потом Tools → Serial Monitor, справа в окне монитора — 115200 и любой конец строки, кроме «No Line Ending».
- **PlatformIO:** `pio device monitor -b 115200` из папки `firmware/`; выход — Ctrl+C.
- **Windows:** PuTTY, тип Serial, порт `COM…` (номер — в Диспетчере устройств, «Порты»), скорость 115200.
- **Linux и macOS:** `screen /dev/ttyACM0 115200` (в macOS — `/dev/cu.usbmodem…`); выход — Ctrl+A, потом K и Y.

Команду наберите и нажмите Enter.

- **Команда `ver`** работает в любой момент. Она отвечает `Прошивка <версия>, плата rev B`.
- **`sensors`** — датчики: первая строка `Ускорение: x …` или «Ускорение: нет новых выборок» (повторите), но не «Акселерометр не отвечает»; вторая начинается с `Свет: есть`, а не `Свет: нет ответа`.
- **Приветствие при включении:** `Брелок с эмоциями, плата rev B, прошивка <версия>. Экран есть, акселерометр есть, свет есть`. Оно печатается один раз, сразу после включения, и обычно до терминала не доходит: порт появляется, когда брелок уже запустился. Не видно приветствия — это не ошибка, проверяйте командами `ver` и `sensors`.

Версия должна совпасть со строкой «Версия» вверху этого файла. У брелока на продажу — с меткой вашей сборки для продажи. Что значит остальное:

- **`-dirty` в конце** — файл собран из исходников с незакоммиченными правками. Такую прошивку не ставят на брелоки для продажи.
- **`unknown`** — файл собран без git, например из архива исходников. Какая это версия, не узнать.
- **На `ver` брелок отвечает «Не знаю такую команду»** — прошивка старая, собрана до того, как в неё добавили версию. Залейте новую. Прошивка до коммита `098681e` на итоговой плате rev B ещё и не заряжает ячейку (CHG_EN на P0.24 она не включает) и не видит акселерометр (ищет его по адресу 0x18, а на плате 0x19): `sensors` у неё пишет «Акселерометр не отвечает».
